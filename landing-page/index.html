The problem

Allowlisting functions isn't enough

TEEs, MPC and session keys all protect the key. If your server or its API keys are compromised, the attacker signs whatever it wants. A wallet that only checks function names will happily approve an attacker.

typical agent wallet
// policy: allow approve() and deposit()
USDC.approve(VAULT, amount)        allowed
VAULT.deposit(amount)              allowed

// server compromised
USDC.approve(ATTACKER, MAX)       allowed
funds drained

Checks which function. Not where the money goes.

AgentWalletKit
// registry: MORPHO_VAULT → ERC4626_ADAPTER
executeViaAdapter(ERC4626_ADAPTER, MORPHO_VAULT, deposit)  runs

// server compromised
executeViaAdapter(ERC4626_ADAPTER, ATTACKER, deposit)
  reverts: AdapterNotRegistered
execute(USDC, transfer(ATTACKER))   reverts: NotAllowed

Checks the adapter and the target onchain, in the transaction.

Security model

Assume your server gets compromised

Build as if it already happened. Here's what someone holding your agent keys can and can't do to an AgentWalletKit wallet.

An attacker can't

  • Send tokens to an address of their choosing
  • Call a contract that isn't registered for an adapter
  • Use the wallet's generic execute; it always reverts
  • Withdraw to themselves: withdrawals are owner-only
  • Upgrade the wallet: only the owner can, and only to the approved version

They're limited to

  • Registered adapters on registered targets, like a vault you approved
  • Swaps and transfers your policies allow
  • The time it takes you to respond: remove the operator, pause the registry

The full list of trade-offs is in the known risks.

TEE / SGX

Only as safe as the keys and environment you pass in.

MPC wallets

Leaked node keys sign anything.

Multisig

Checks who signs, not what gets signed.

Rate limits

Attackers drain slowly instead.

Features

The wallet layer for autonomous agents

Target-level validation

Every call names an adapter and a target. The wallet checks the pair against the registry before anything runs.

Adapter registry

One small, immutable adapter per protocol. It validates the call and only touches registered addresses.

Many agent types

One factory serves several agent profiles. Each profile gets its own registry, so a vault agent and a lending agent can't use each other's protocols.

ERC-4337 native

Gas sponsorship through paymasters and batched calls. Owners can sign with a key or, for a Safe, through ERC-1271.

Emergency controls

Pause a registry, remove a target or revoke an operator instantly. Admin changes go through a timelock.

Owners stay in charge

Withdraw at any time, block any adapter or target for their own wallet, and choose whether to upgrade.

Audited

Reviewed by Nethermind. The report is in the repository.

Open source

Use it as is, write your own adapters, or run a self-managed wallet without a factory.

How it works

Every agent call takes the same path

  1. 01

    Sign

    Your server signs a UserOperation for the wallet.

  2. 02

    Authorize

    The wallet accepts the owner, or an operator calling adapters.

  3. 03

    Check

    The registry must map this target to this adapter.

  4. 04

    Execute

    The adapter runs inside the wallet and calls the protocol.

Solidity
// 1. The operator creates a wallet for the user
AgentWallet wallet = factory.createAgentWallet(owner, agentIndex, USDC, VAULT_PROFILE, feePlans);

// 2. The admin registers a vault for the ERC-4626 adapter (through the timelock)
registry.setTargetAdapter(MORPHO_VAULT, ERC4626_ADAPTER);

// 3. The agent deposits; any other target reverts
wallet.executeViaAdapter(ERC4626_ADAPTER, MORPHO_VAULT, abi.encodeCall(adapter.deposit, (amount)));

FAQ

Questions

What happens if my server keys are stolen?

The attacker can only call registered adapters on registered targets, such as moving funds between vaults you approved. They can't send funds to their own address or call unregistered contracts; the wallet enforces this onchain. Remove the operator and pause the registry to stop them.

How is this different from a multisig?

A multisig controls who can sign. AgentWalletKit controls what can be executed. Even an authorized operator can't get around the adapter registry.

Can I add new protocols?

Yes. Write an adapter, get it reviewed, deploy it, then register it and its targets in the registry. Wallets can use it straight away.

What if a protocol gets hacked?

The emergency role can remove that target or pause the whole registry at once, which stops every agent from touching it.

Does it work with existing DeFi protocols?

Yes. Adapters call the protocols' normal interfaces, like ERC-4626 vaults, Aave, Morpho and Uniswap V3. The protocols don't need to change.

Which chains are supported?

Any EVM chain with the ERC-4337 EntryPoint. It runs on Base mainnet today, where it has secured 5,000+ agents and $300M+ in volume.
