# Changelog

## Unreleased

### Agent wallet V3, agent profiles and borrow agents

- `AWKAgentWalletFactory` / `YieldSeekerAgentWalletFactory`: each wallet has an agent profile (its agent type) that selects its adapter registry. `setAdapterRegistry(agentProfile, registry)` sets it and `adapterRegistry(agentProfile)` reads it; wallets store their agent profile at `initialize` (fixed for life). The fee tracker stays a single factory setting. `createAgentWallet(owner, index, baseAsset, agentProfile, feePlans)` also sets the wallet's plan per fee type (`FeePlanChoice[]`) and reverts `NoFeeTracker` until the factory has a tracker. Deployed as a new factory; the V2 factory stays live.
- `AWKAgentWalletV3` / `YieldSeekerAgentWalletV3` replace V2 (same storage): the owner may withdraw any token the fee tracker accounts for (`isAccountedToken`: the base asset, or e.g. a borrowed token). Every owner withdrawal first lets the fee modules collect what they are owed from the base asset (`FeeActions.TRANSFER_OUT`, gas-limited and failure-tolerant so it can never block the exit), then sends exactly the amount requested (or the rest, for withdraw-all); `withdrawableBalance(asset)` shows the amount net of fees owed. `collectFees()` is removed: fees are paid as they arise (see below). `AWKSelfManagedAgentWalletV3` runs without a factory (owner-set registry and operators, owner-chosen upgrades). V1/V2 wallets on the V2 factory are unchanged.
- Wallets read the adapter registry (`factory.adapterRegistry(agentProfile)`) and the fee tracker (`factory.feeTracker()`) from the factory when they use them, so a change applies to every wallet at once. Only the agent operators are still copied into the wallet (`validateUserOp` may only read the wallet's own storage), so `syncFromFactory()` now syncs operators only and emits `SyncedFromFactory(agentOperators)`; `InvalidRegistry` and `InvalidFeeTracker` are removed. The storage fields stay (unused) so the layout doesn't change.
- Removed the V1 wallet sources (`AWKAgentWalletV1.sol`, `AgentWalletV1.sol`) and the V2 storage facade. `AgentWalletStorageV3` keeps the V1 namespace and appends `agentProfile`; `YieldSeekerStorageV1` and the V1 errors now live in the V3 files; `IAWKAgentWalletFactory` no longer has the parameterless `adapterRegistry()`.
- `YieldSeekerFeeTracker` moved to `src/fees/` and is rewritten: it holds one module per fee type (`setFeeModule` adds or replaces one, and only accepts a module whose `FEE_TRACKER` and `FEE_TYPE` match), each fee type's plans, each wallet's plans, the wallet factory and the fee collector (all set by the timelock; the only role is the admin, as on main), and combines modules for `isAccountedToken` and `feesOwedInBaseAsset` (each module called with a gas limit, and the caller must leave enough gas for it; a failing module counts as accounting for nothing and owing nothing, and the base asset is always accounted for). A plan is the module's own `Plan` struct (its rates), ABI-encoded and validated by the module (`isValidPlan`): created by the timelock (`createPlan`), never changed. A replacement module must accept every existing plan and can add new ones. Only the wallet factory sets a wallet's plans, at creation (`initWalletPlans`), and they never change; unlisted fee types use plan 0. The plan manager role is gone. It no longer has the vault accounting interface.
- Fees are modules that decide what each action costs: adapters only report what the wallet did to the tracker (`reportAction(action, data)`, with actions and their data structs in `FeeActions`: deposit, withdraw, swap, claim, debt change), which passes it to every module (`onAction`, tracker-only). Each module pays its fees from the wallet's base asset left by the modules before it; the adapter sends the total to the fee collector in one transfer. A new fee type needs only a new module; a new action needs only a `FeeActions` ID and struct (modules ignore actions they don't know).
- `YieldSeekerYieldFeeModule` (`YIELD_FEE`, replacing the audited vault accounting) keeps only a cost basis per target: a withdrawal releases the share of it matching the share of the position withdrawn (vault shares, or balance for rebasing vaults), and anything received above it is yield; base-asset claims and the base asset received from selling any other token are yield too. The rate comes from the wallet's plan. Per-token reward fee bookkeeping, share tracking, the double-charge guards and the exchange-rate conversion are gone.
- Compound V2 / Moonwell: `withdraw` now redeems a cToken amount (`redeem`) instead of an underlying amount.
- Added `YieldSeekerBorrowFeeModule` (`BORROW_FEE`): yearly fee on borrowed principal per market, charged on the debt seen at the previous report, interest-first repayments; each charged period is converted to the base asset (collateral) with the lending market's own price, reported by the lending adapter, and paid at the first action or outflow that finds base asset in the wallet. Borrowed tokens can be withdrawn in full.
- New V3 vault registry with new vault, reward and swap adapters (the swap adapters are shared with the borrow registry). The V2 vault registry and its adapters stay unchanged for V2 wallets; both vault registries must hold the same targets (see "Two vault registries" in the README).
- Added AWK lending adapters (Aave V3, Aave V4, Morpho Blue). Each market is its own registry target (`marketTarget(market)` = hash of the market bytes), so every market needs a timelocked registration. `checkpoint(market)` moves no funds and reads the market's debt; `_debtPriceInCollateral` reads the market's own oracle (Aave V3 pool oracle, Morpho market oracle, Aave V4 spoke oracle). YieldSeeker versions require collateral = base asset and report every debt change and checkpoint, with the market's price, to the fee modules.
- Swap rules moved into swap policies, one per agent profile in the factory (`swapPolicy`, timelock `setSwapPolicy`, read at every swap so a policy can be replaced on its own). Swap adapters (Uniswap V3, Aerodrome V2/CL) share `YieldSeekerSwapAdapter`, take only router arguments and report the action the policy returns; a base-asset sale must leave no fees owed. `YieldSeekerVaultSwapPolicy`: reward tokens → base asset, as before. `YieldSeekerBorrowSwapPolicy`: also base asset → a borrowed token, at most `MAX_SLIPPAGE_BPS` below the oracle; borrowed tokens can't be sold. New `FeeActions.REWARD_SALE`: the yield fee charges only reward sales, not other trades (`SWAP`).
- Added `YieldSeekerPriceOracle` (Chainlink feeds, per-asset staleness, L2 sequencer uptime check), used only for the borrow swap policy's price floor when selling the base asset.
- Added `YieldSeekerWalletLinkRegistry` and `YieldSeekerAgentTransferAdapter`: owner-linked transfers between agent wallets of the same owner and factory; both wallets' trackers must account for the token, and fees owed are settled before the exact amount moves.
- `script/Deploy.s.sol` deploys the V3 contracts and schedules one timelock batch that wires the factory, tracker, fee modules, the V3 vault registry (every V2 vault registry target copied onto the matching V3 adapter, plus wallet links) and the borrow registry (routers, Merkl, wallet links). `RegisterVault.s.sol` registers a vault in both vault registries in one batch. Borrow markets and price feeds are registered with `RegisterBorrowMarket.s.sol` (decodes and validates the market) and `SetPriceSource.s.sol` (checks the feed). `deployments.json` keeps the V2 system (factory, implementation, FeeTracker, vault registry and its adapters) under `agentWalletV2*` keys; existing users move to new wallets by withdrawing to the new wallet address.

### Agent wallet V2

- Added `AWKAgentWalletV2` and `YieldSeekerAgentWalletV2` with EntryPoint-relayed owner actions.
- Blocklist management, ERC20/ETH withdrawals, synchronization, and UUPS upgrades can be paymaster-relayed; owner signatures remain required.
- Operator signatures remain limited to adapter execution.
- Added `AgentWalletStorageV2` as an explicit facade over the unchanged V1 storage layout.
- Existing V1 wallets retain their state when upgraded; V1 implementation behavior remains unchanged.
