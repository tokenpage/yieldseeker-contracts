# Changelog

## Unreleased

### Agent wallet V3, agent profiles and borrow agents

- `AWKAgentWalletFactory` / `YieldSeekerAgentWalletFactory`: each wallet has an agent profile (its agent type) that selects its adapter registry, and in the YieldSeeker factory also its fee tracker and swap policy: `setAdapterRegistry` / `setFeeTracker` / `setSwapPolicy(agentProfile, …)` set them and `adapterRegistry` / `feeTracker` / `swapPolicy(agentProfile)` read them (events `RegistryUpdated`, `FeeTrackerUpdated`, `SwapPolicyUpdated`; the unprofiled `TrackerUpdated` is removed). Wallets store their agent profile at `initialize` (fixed for life) and copy all three when they sync. `createAgentWallet(owner, index, baseAsset, agentProfile, feePlans)` also sets the wallet's plan per fee type (`FeePlanChoice[]`) in its profile's tracker. Deployed as a new factory; the V2 factory stays live.
- `AWKAgentWalletV3` / `YieldSeekerAgentWalletV3` replace V2 (same storage; `YieldSeekerStorageV1` appends `swapPolicy`): the owner may withdraw any token the fee tracker accounts for (`isAccountedToken`: the base asset, or e.g. a borrowed token). Every owner withdrawal first lets the fee modules collect what they are owed from the base asset (`FeeActions.TRANSFER_OUT`, gas-limited and failure-tolerant so it can never block the exit), then sends exactly the amount requested (or the rest, for withdraw-all); `withdrawableBalance(asset)` shows the amount net of fees owed. `collectFees()` is removed: fees are paid as they arise (see below). `AWKSelfManagedAgentWalletV3` runs without a factory (owner-set registry and operators, owner-chosen upgrades). V1/V2 wallets on the V2 factory are unchanged.
- Removed the V1 wallet sources (`AWKAgentWalletV1.sol`, `AgentWalletV1.sol`) and the V2 storage facade. `AgentWalletStorageV3` keeps the V1 namespace and appends `agentProfile`; `YieldSeekerStorageV1` and the V1 errors now live in the V3 files; `IAWKAgentWalletFactory` no longer has the parameterless `adapterRegistry()`.
- `YieldSeekerFeeTracker` moved to `src/fees/` and is rewritten: it holds one module per fee type (`setFeeModule` adds or replaces one, and only accepts a module whose `FEE_TRACKER` and `FEE_TYPE` match), each fee type's plans, each wallet's plans, the wallet factory and the fee collector (all set by the timelock; the only role is the admin, as on main), and combines modules for `isAccountedToken` and `feesOwedInBaseAsset` (each module called with a gas limit, and the caller must leave enough gas for it; a failing module counts as accounting for nothing and owing nothing, and the base asset is always accounted for). A plan is the module's own `Plan` struct (its rates), ABI-encoded and validated by the module (`isValidPlan`): created by the timelock (`createPlan`), never changed. A replacement module must accept every existing plan and can add new ones. Only the wallet factory sets a wallet's plans, at creation (`initWalletPlans`), and they never change; unlisted fee types use plan 0. The plan manager role is gone. It no longer has the vault accounting interface.
- Fees are modules that decide what each action costs: adapters only report what the wallet did to the tracker (`reportAction(action, data)`, with actions and their data structs in `FeeActions`: deposit, withdraw, swap, claim, debt change), which passes it to every module (`onAction`, tracker-only). Each module pays its fees from the wallet's base asset left by the modules before it; the adapter sends the total to the fee collector in one transfer. A new fee type needs only a new module; a new action needs only a `FeeActions` ID and struct (modules ignore actions they don't know).
- `YieldSeekerYieldFeeModule` (`YIELD_FEE`, replacing the audited vault accounting) keeps only a cost basis per target: a withdrawal releases the share of it matching the share of the position withdrawn (vault shares, or balance for rebasing vaults and lending collateral), and anything received above it is yield; base-asset claims and the base asset received from reward sales (`REWARD_SALE`) are yield too. The rate comes from the wallet's plan. Per-token reward fee bookkeeping, share tracking, the double-charge guards and the exchange-rate conversion are gone.
- Compound V2 / Moonwell: `withdraw` now redeems a cToken amount (`redeem`) instead of an underlying amount. The backend must send cToken amounts for V3 wallets (`assets × 1e18 / exchangeRateCurrent`, or the full balance); V2 wallets keep the V2 adapter.
- Added `YieldSeekerBorrowFeeModule` (`BORROW_FEE`): yearly fee on each market's debt (interest included), keyed by the market's registry target and charged on the debt seen at the previous report; each charged period is converted to the base asset (collateral) with the lending market's own price, reported by the lending adapter, and paid at the first action or outflow that finds base asset in the wallet. Borrowed tokens can be withdrawn in full.
- New V3 vault registry with new vault, reward and swap adapters (the swap adapters are shared with the borrow registry). The V2 vault registry and its adapters stay unchanged for V2 wallets; both vault registries must hold the same targets (see "Two vault registries" in the README).
- Added AWK lending adapters (Aave V3, Aave V4, Morpho Blue). Each market is its own registry target (`marketTarget(market)` = hash of the market bytes), so every market needs a timelocked registration. `checkpoint(market)` moves no funds and reads the market's debt; `_debtPriceInCollateral` reads the market's own oracle (Aave V3 pool oracle, Morpho market oracle, Aave V4 spoke oracle); `_collateralOf` reads the wallet's collateral. The Aave V3 adapter needs an Aave V3.3+ pool (`getReserveAToken` / `getReserveVariableDebtToken`, about 20k gas cheaper per read than `getReserveData`). YieldSeeker versions require collateral = base asset, report every debt change and checkpoint, with the market's price, to the fee modules, and report collateral supplied and withdrawn as a yield-fee position (target = `marketTarget(market)`), so collateral interest is charged like vault yield. The YieldSeeker Aave V3 version only accepts eMode 0 (`EModeNotAllowed`).
- Swap rules moved into swap policies, one per agent profile, set in the factory (`setSwapPolicy`, timelock) and copied by wallets at sync (`swapPolicy()`), so a policy can be replaced on its own. Swap adapters (Uniswap V3, Aerodrome V2/CL) share `YieldSeekerSwapAdapter`, take only router arguments and report the action the policy returns; a base-asset sale must leave no fees owed (`FeesOwed`). `YieldSeekerVaultSwapPolicy`: reward tokens → base asset, as before. `YieldSeekerBorrowSwapPolicy`: also base asset → a borrowed token, at most `MAX_SLIPPAGE_BPS` below the oracle; borrowed tokens can't be sold. New `FeeActions.REWARD_SALE`: the yield fee charges only reward sales, not other trades (`SWAP`).
- Added `YieldSeekerPriceOracle` (Chainlink feeds, per-asset staleness, L2 sequencer uptime check), used only for the borrow swap policy's price floor when selling the base asset.
- Added `YieldSeekerWalletLinkRegistry` and `YieldSeekerAgentTransferAdapter`: owner-linked transfers between agent wallets of the same owner and factory; both wallets' trackers must account for the token, and fees owed are settled before the exact amount moves.
- `script/Deploy.s.sol` deploys the V3 contracts and schedules one timelock batch that wires the factory (registry, fee tracker and swap policy per agent profile), the two fee trackers and their modules (vault: `vaultYieldFeeModule`; borrow: `borrowYieldFeeModule` + `borrowFeeModule`), the V3 vault registry (every V2 vault registry target copied onto the matching V3 adapter, plus wallet links) and the borrow registry (routers, Merkl, wallet links). `RegisterVault.s.sol` registers a vault in both vault registries in one batch. Borrow markets and price feeds are registered with `RegisterBorrowMarket.s.sol` (decodes and validates the market) and `SetPriceSource.s.sol` (checks the feed). `deployments.json` keeps the V2 system (factory, implementation, FeeTracker, vault registry and its adapters) under `agentWalletV2*` keys; existing users move to new wallets by withdrawing to the new wallet address.
- Compound V3 (Comet) withdrawals are capped at the wallet's Comet balance, so a withdraw can never borrow against collateral someone supplied to the wallet's account (that loop could inflate the yield fee cost basis). The yield fee treats base asset received from a position the wallet held nothing in as yield. The Moonwell reward adapter also reports rewards paid in the base asset.
- Borrow fee: each position keeps the market's last reported price, so a period reported without a price (debt repaid outside the adapters) is still charged; the lending adapter reads the price whenever there is debt before or after the action. Yield and borrow fees round up. Swap policies never sell a token the wallet's registry maps as a target (a position), whatever the sell policy allows. Aave V3 `withdrawCollateral` above the balance withdraws everything. `RegisterBorrowMarket` requires canonical market bytes; `RegisterVault` salts include the block number.
- Base → borrowed swaps are capped at the wallet's debt in that token: the borrow fee module keeps `tokenDebt(wallet, token)` (summed over markets at their last report) and the borrow swap policy reverts `SwapAboveDebt` if the wallet would hold more of the token than it owes. The Aave V3 lending adapter enables the supplied asset as collateral on every supply. The Aave V4 lending adapter reports the spoke's returned asset amounts (it returns shares, then assets).
- Every adapter has one shape: `execute` decodes and validates the input, calls the operation (`_depositOperation` / `_withdrawOperation`, `_swapOperation`, `_claimOperation`, the lending operations), which YieldSeeker overrides to add its rules and fee reports, and the operation calls the protocol implementation (`_deposit` / `_withdraw`, `_swap`, `_claim`, …). The swap before/after hooks (`_beforeSwap`, `_afterSwapInternal`, `SwapBalanceSnapshot`) are gone. The four YieldSeeker vault adapters share `YieldSeekerVaultAdapter`, which measures a withdrawal's share of the position as the change in the wallet's vault token balance (shares, cTokens, or the rebasing aToken / Comet balance). `AWKCompoundV2Adapter` wraps native ETH from a redeem back into the underlying. Vault events are emitted by `execute`.
- `SetPriceSource.s.sol` rejects feeds that aren't aggregator proxies (`aggregator()`), so a protocol wrapper that rewrites timestamps can't become a price source. README: never turn on `allowSellingAllTokens`; a replacement borrow fee module must also import `tokenDebt`.
- Operator revocation no longer waits for the timelock or for owners: the factory takes an `emergencyAdmin` (constructor `(admin, emergencyAdmin, agentOperator)`) whose `EMERGENCY_ROLE` can `removeAgentOperator(operator)` at once (adding operators stays with the admin), and `syncFromFactory()` is callable by anyone (it takes no input and only copies the factory's configuration), so the platform syncs every wallet itself. `Deploy.s.sol` refuses to replace a registry, fee tracker or fee module already in use (`Refusing to replace …`). Unpausing a registry stays with the timelock.
- Wallet signature validation returns `SIG_VALIDATION_FAILED` for a malformed signature instead of reverting (`ECDSA.tryRecover`), as ERC-4337 asks, so bundlers can estimate gas with dummy signatures. The storage libraries' `@custom:storage-location erc7201:` tags are replaced by the real slot formula (a plain `keccak256` of the namespace, unchanged).
- Vault adapters measure every amount from balances: ERC4626 and Aave V3 withdrawals report the base asset actually received (not `redeem` / `withdraw` return values), like Compound V2 and V3. The Comet adapter resets its approval after `supply`, since Comet reads `type(uint256).max` as "supply my borrow balance" and `deposit(max)` used to leave an unlimited approval.
- Merkl: the adapter's `claim` drops the `users` argument and becomes `claim(tokens, amounts, proofs)`; the adapter claims for the wallet itself (one `users` entry per token, all the wallet). The backend must encode the 3-argument call for V3 wallets; V2 wallets keep the V2 Merkl adapter and its 4-argument call.
- Owner-signed UserOperations also accept a contract owner's ERC-1271 approval (`isValidSignature`, read-only), so an integrator can sponsor withdrawals for users whose owner is a Safe or smart wallet. ECDSA is checked first, so EOAs (including EIP-7702 ones) are unchanged; operator signatures stay ECDSA-only and limited to adapter execution.
- `upgradeToLatest` syncs through the upgrade call (`upgradeToAndCall(impl, syncFromFactory())`), so the **new** implementation's sync runs; previously the old code's sync ran after the switch, so fields a new version syncs stayed unset until the next sync.
- `YieldSeekerAgentWalletV3` disables the inherited 3-argument `initialize(owner, index, profile)` (`NotAllowed`); its wallets are only initialized with the base asset. New test: an owner can't skip fee settlement with any gas limit (withdrawal either reverts or pays the full fee, swept from 60k to 3M gas).

### Agent wallet V2

- Added `AWKAgentWalletV2` and `YieldSeekerAgentWalletV2` with EntryPoint-relayed owner actions.
- Blocklist management, ERC20/ETH withdrawals, synchronization, and UUPS upgrades can be paymaster-relayed; owner signatures remain required.
- Operator signatures remain limited to adapter execution.
- Added `AgentWalletStorageV2` as an explicit facade over the unchanged V1 storage layout.
- Existing V1 wallets retain their state when upgraded; V1 implementation behavior remains unchanged.
