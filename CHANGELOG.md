# Changelog

## Unreleased

### Agent wallet V3, agent profiles and borrow agents

- `AWKAgentWalletFactory` / `YieldSeekerAgentWalletFactory`: each wallet has an agent profile (its agent type) that selects its adapter registry. `setAdapterRegistry(agentProfile, registry)` sets it and `adapterRegistry(agentProfile)` reads it; wallets store their agent profile at `initialize` (fixed for life) and read their registry with it when they sync. The fee tracker stays a single factory setting. `createAgentWallet(owner, index, baseAsset, agentProfile, feePlans)` also sets the wallet's fee plans. Deployed as a new factory; the V2 factory stays live.
- `AWKAgentWalletV3` / `YieldSeekerAgentWalletV3` replace V2 (same storage): the owner may withdraw a token the fee tracker tracks (`tracksToken`: the base asset, or e.g. a borrowed token), minus what it holds back for fees (`feesHeld`); wallets still follow the factory's tracker on every sync. `collectFees()` is removed: adapters pay fees as they arise (see below), so a wallet's base-asset balance has no pending fees. `AWKSelfManagedAgentWalletV3` runs without a factory (owner-set registry and operators, owner-chosen upgrades). V1/V2 wallets on the V2 factory are unchanged.
- Removed the V1 wallet sources (`AWKAgentWalletV1.sol`, `AgentWalletV1.sol`) and the V2 storage facade. `AgentWalletStorageV3` keeps the V1 namespace and appends `agentProfile`; `YieldSeekerStorageV1` and the V1 errors now live in the V3 files; `IAWKAgentWalletFactory` no longer has the parameterless `adapterRegistry()`.
- `YieldSeekerFeeTracker` moved to `src/fees/` and is rewritten: it holds one module per fee type (`setFeeModule` adds or replaces one), each fee type's plans, each wallet's plans and the fee collector, and combines modules for `tracksToken` / `feesHeld` (each module called with a gas limit; a failing module counts as tracking nothing and holding nothing, and the base asset is always tracked). A plan is a rate for one fee type: created by the timelock (`createPlan`), never changed. The factory sets a wallet's plans at creation and they never change; unlisted fee types use plan 0. The plan manager role is gone. It no longer has the vault accounting interface.
- Fees are modules that decide what each action costs: adapters only report what the wallet did, as `onAction(action, data)` on every module, with actions and their data structs in `FeeActions` (deposit, withdraw, swap, claim, debt change). Each module pays its fees from the wallet's base asset and the adapter sends each payment to the fee collector. A new fee type needs only a new module; a new action needs only a `FeeActions` ID and struct (modules ignore actions they don't know).
- `YieldSeekerYieldFeeModule` (`YIELD_FEE`, replacing the audited vault accounting) keeps only a cost basis per target: a withdrawal releases the share of it matching the share of the position withdrawn (vault shares, or balance for rebasing vaults), and anything received above it is yield; base-asset claims and the base asset received from selling any other token are yield too. The rate comes from the wallet's plan. Per-token reward fee bookkeeping, share tracking, the double-charge guards and the exchange-rate conversion are gone.
- Compound V2 / Moonwell: `withdraw` now redeems a cToken amount (`redeem`) instead of an underlying amount.
- Added `YieldSeekerBorrowFeeModule` (`BORROW_FEE`): yearly fee on borrowed principal per market, charged on the debt seen at the previous report, interest-first repayments; counted in the borrowed token, due in the base asset (collateral) at the oracle price and paid at the first action that leaves base asset in the wallet. Borrowed tokens are never held back.
- New V3 vault registry with new vault, reward and swap adapters (the swap adapters are shared with the borrow registry). The V2 vault registry and its adapters stay unchanged for V2 wallets; both vault registries must hold the same targets (see "Two vault registries" in the README).
- Added AWK lending adapters (Aave V3, Aave V4, Morpho Blue). Each market is its own registry target (`marketTarget(market)` = hash of the market bytes), so every market needs a timelocked registration. YieldSeeker versions require collateral = base asset and report every debt change to the fee modules.
- Swap adapters (Uniswap V3, Aerodrome V2/CL) now share `YieldSeekerSwapAdapter`: reward tokens → base asset as before, plus base asset → a token a fee module accounts for in the wallet (e.g. a borrowed token), at most `MAX_SLIPPAGE_BPS` below the oracle and never spending base asset held back for fees.
- Added `YieldSeekerPriceOracle` (Chainlink feeds, per-asset staleness, L2 sequencer uptime check).
- Added `YieldSeekerWalletLinkRegistry` and `YieldSeekerAgentTransferAdapter`: owner-linked transfers between agent wallets of the same owner and factory; both wallets' trackers must allow the token.
- `script/Deploy.s.sol` deploys the V3 contracts and schedules one timelock batch that wires the factory, tracker, fee modules, the V3 vault registry (every V2 vault registry target copied onto the matching V3 adapter, plus wallet links) and the borrow registry (routers, Merkl, wallet links). `RegisterVault.s.sol` registers a vault in both vault registries in one batch. Borrow markets and price feeds are registered with `RegisterBorrowMarket.s.sol` (decodes and validates the market) and `SetPriceSource.s.sol` (checks the feed). `deployments.json` keeps the V2 system (factory, implementation, FeeTracker, vault registry and its adapters) under `agentWalletV2*` keys; existing users move to new wallets by withdrawing to the new wallet address.

### Agent wallet V2

- Added `AWKAgentWalletV2` and `YieldSeekerAgentWalletV2` with EntryPoint-relayed owner actions.
- Blocklist management, ERC20/ETH withdrawals, synchronization, and UUPS upgrades can be paymaster-relayed; owner signatures remain required.
- Operator signatures remain limited to adapter execution.
- Added `AgentWalletStorageV2` as an explicit facade over the unchanged V1 storage layout.
- Existing V1 wallets retain their state when upgraded; V1 implementation behavior remains unchanged.
